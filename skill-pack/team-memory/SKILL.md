# Team Memory

A team without shared memory repeats its mistakes: it re-asks settled
questions, violates old corrections, and contradicts itself across
sessions. This skill gives a team one memory that every member reads
and writes.

## Two memories, two jobs

- Each agent keeps its own private notes for its own work.
- The team keeps one shared memory for facts, decisions, and
  corrections that any member may need. It survives across sessions
  and every team member can read it.
- Team facts, decisions, and owner corrections always go to shared
  memory, never to private notes alone.

## Recall before you work

- Before starting work on a topic the team has discussed, recall it
  first: past decisions, standing rules, and corrections the owner
  has given.
- A recalled correction is binding. Do not repeat work that
  contradicts it, and do not ask the owner a question the memory
  already answers.

## Save after the owner speaks

- After the owner gives a correction, a decision, or a lasting
  preference, save it to shared memory in full, as if briefing an
  absent teammate, and sign it with your own name.
- Write facts, not transcripts: what was decided, what it replaces,
  and when it happened.

## Newest wins, removal needs an order

- When a new correction contradicts an old memory, the newest wins:
  save the correction, and note what it replaced.
- Remove a wrong memory only when the owner orders it. Never quietly
  drop a memory because it is inconvenient.

## Personal data stays out

- Never copy personal data into shared memory: contact details,
  private files, credentials, and anything the owner has not meant
  for the whole team. Reference such items, do not duplicate them.
